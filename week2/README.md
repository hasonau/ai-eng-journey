# Week 2 — LLM APIs, Open Models & Streaming

## What I Learned

### 1. Working with LLM APIs

- How to interact with hosted LLMs using the Groq Python SDK.
- How to select models using their model IDs.
- How to configure generation parameters such as `temperature`, `max_completion_tokens`, and `reasoning_effort`.
- How to retrieve generated content and token usage from API responses.

### 2. Streaming vs Non-Streaming

**Non-streaming:** The API returns the complete response after generation finishes.

**Streaming:** The API sends the response incrementally in chunks, allowing the application to display content as it is generated.

Important implementation details:

- Enable streaming with `stream=True`.
- Read generated text from `chunk.choices[0].delta.content`.
- A chunk can contain metadata without any actual text.
- The final chunks can contain usage information and the finish reason.
- Streaming improves perceived responsiveness, but does not necessarily reduce total generation time.

### 3. Understanding Performance Metrics

I implemented measurements for the following metrics:

| Metric            | Meaning                                                             |
| ----------------- | ------------------------------------------------------------------- |
| TTFT              | Time until the first non-empty content chunk arrives.               |
| Total latency     | Time from sending the request until the response is fully received. |
| Prompt tokens     | Tokens consumed by the input.                                       |
| Completion tokens | Tokens generated by the model.                                      |
| Total tokens      | Input and output token usage combined.                              |
| Completion time   | Provider-reported time spent generating the completion.             |
| TPS               | Completion tokens divided by completion time.                       |
| Content chunks    | Number of chunks containing generated text.                         |

I also learned that **content chunks are not the same as tokens**. One chunk can contain multiple tokens.

TTFT is meaningful for streaming because the application can observe when the first content arrives. A non-streaming response does not expose that intermediate event.

### 4. Benchmarking Models

I compared two models:

- `openai/gpt-oss-120b`
- `qwen/qwen3.8-27b`

Experiment configuration:

- Five trials per model per mode.
- Both streaming and non-streaming requests.
- Same question and generation settings.
- Temperature: `0.3`.
- Reasoning effort: `low`.
- Maximum completion tokens: `400`.

The experiment recorded 20 total results in `benchmark_results.csv`.

## Benchmark Results

Average results across five trials:

### Streaming

| Metric            | GPT-OSS 120B | Qwen 3.8 27B |
| ----------------- | -----------: | -----------: |
| TTFT              |      0.566 s |      0.225 s |
| Total latency     |      0.664 s |      0.334 s |
| Completion tokens |         65.2 |         98.8 |
| TPS               |       478.39 |       506.84 |

### Non-Streaming

| Metric            | GPT-OSS 120B | Qwen 3.8 27B |
| ----------------- | -----------: | -----------: |
| Total latency     |      0.619 s |      0.415 s |
| Completion tokens |         57.2 |        100.4 |
| TPS               |       479.34 |       558.05 |

_All measurements are from my experiment and are not universal model performance guarantees._

## What I Observed

1. Qwen had lower average TTFT and end-to-end latency in both modes in this experiment.
2. Qwen generated considerably more completion tokens than GPT-OSS.
3. Qwen also achieved higher average TPS in this sample.
4. Streaming allowed me to measure TTFT and observe content arriving incrementally.
5. A model's end-to-end latency and its actual generation speed are different measurements.

**Important limitation:** Both models generated different amounts of text. Therefore, this was a practical comparison under identical settings, not a perfectly controlled test of generation speed. Network conditions, provider queueing, and output length can all affect results.
